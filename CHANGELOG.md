# Changelog

All notable changes to Uncoil are recorded here.

Uncoil follows [Semantic Versioning](https://semver.org). The `0.x` series *is*
the beta: features bump the minor, fixes bump the patch, and `1.0.0` will be the
statement that the app is out of beta. Each released section's body is used
verbatim as the GitHub Release notes and as the in-app update notes, so the
release notes are written once, here.

## Unreleased

## [0.1.0] - 2026-08-04

First public beta. Everything Uncoil does today ships in this release — the
dated sections at the end of this file are development entries from before the
project was versioned, and they are part of 0.1.0 too.

### Added

- Uncoil is free software, published under the Apache License 2.0 with a README that explains what it is and how to build it. The only dependency is SwiftTerm (MIT), and the build instructions no longer point at one particular Mac's disk.
- Real multi-window support. ⌘N already opened a second window, but every window read the same stored selection and fought over it; a window now takes an identity when it appears, keeps its own selection and split pane, remembers its frame under a name of its own, and gives everything back when it closes. Opening one by hand asks what it should open on — clone the main window, clone a named window, or start empty — and a clone opens on the source's project and view rather than its session. The arrangement comes back at launch, and quitting is told apart from closing so the last window out does not record a single-window app.
- Settings › CLI Tools answers "what is on this Mac" in one place: per agent, how it was installed, its version, the path on `PATH`, what that path resolves to, and the exact command an update would run. The resolved path is the part that matters — the launcher is nearly always a symlink, and which install a tool belongs to is only visible at the other end of it. "Up to date" is no longer shown before both halves of the comparison are in.
- The project list belongs to the window. An empty window is empty including its sidebar, and a project opened in one window is in that window; its empty sidebar lists the projects the app has and this window does not, one click each, so a clean window is not a dead end. Windows that predate this — the one you already had, and every window restored from an older version — go on showing every project, including ones added later.
- A session is shown in one window at a time, and the others say so. This was already true of the machinery and not of the interface: one `TerminalView` exists per session, an `NSView` has one superview, and a second window mounting the same terminal took it out of the first silently, mid-render. Selecting a session claims it, navigating away gives it up, and claiming never steals — a window that does not have it draws "This session is open in another window" where the terminal would be, names the window that does, and offers both answers: go there, or move it here. Dragging a terminal into a popout still takes it, because someone who did that meant to, and the popout is a window under the same rule.

### Fixed

- Updating an agent CLI installed through a Node version manager works. Reported as "Gemini shows an update but updating fails", and it was three defects at once: install detection asked for substrings that a path like `~/.nvm/versions/node/v24.1.0/bin/gemini` does not contain, so it read as unknown; there was no Gemini update command at all beyond the Homebrew one; and the Homebrew command used the tool's own name, while Homebrew calls them `gemini-cli` and `claude-code`. Detection now follows the symlink — a global npm package always lands under `lib/node_modules` whoever manages the Node — and runs that Node's own npm, so the update goes back where the binary came from rather than into whichever Node the login shell happens to resolve. An install that still cannot be placed says so instead of guessing. And the outcome is checked rather than trusted: the version before and after are compared, so "the command succeeded and nothing moved" is reported as exactly that.
- A request from the menu bar, a notification or the command palette now lands in exactly one window instead of every window at once. A session already open somewhere goes to the window that has it, in preference to the one in front — otherwise "take me to my agent" would have been answered with "this session is open in another window".
- ⌘K opens the palette in the window you are in. A single key monitor closed over the first window's palette, so the shortcut toggled one nobody was looking at.

### Changed

- Settings were reorganised around six categories instead of eight. Four of the old ones held a single page — a category of one is a heading pretending to be a group, and it pushed the pages that belong together apart. Pages also sat where they had been written rather than where they are looked for: Quick Launch is a strip in the interface and was filed under Agents; Menu Bar was a category of its own; Status Tracking writes into Claude Code's own `settings.json`, so it is not a privacy setting. The tree is now General · Agents · Notifications · Appearance · **Uncoil** · About, and every page is reachable from a category that lists it.
- Everything about Uncoil's own machinery is under one heading: Permissions, Uncoil MCP, Agent Status Hooks, Drivers, GitHub and Data and Transcripts. Permissions and the control plane that enforces them had been filed under different categories, which is exactly the question nobody would think to ask in two places.
- "Mode and Keyboard" was two unrelated things on one page: a per-agent trust policy and how the keyboard behaves in a prompt. It is now **Working Mode** under Agents and **Keyboard and Input** under General — which also collects the Option-as-Meta toggle that had been sitting in a "Keyboard" section on the General page, so keyboard settings are no longer in two places. Deep links written against the old page still resolve.
- The working-mode step in first-run setup marks each agent with its own logo. Three cards under one generic glyph read as three copies of the same setting, which is the one thing that page must not say.

- The interface has depth and weight it did not have before. Corner radii were nine different values across the app and are now three, tied to what a surface is — chip, panel, or a sheet that floats above the window — alongside new spacing, motion and elevation tokens. Panels catch a hairline of light along the top edge, floating surfaces cast a real shadow whose density follows the palette (a light window needs a darker shadow than a dark one), and the sidebar sits on its own surface instead of sharing the detail column's fill, so the window reads as two planes rather than one field split by a line. Every animation moved from `easeOut` to a high-damping spring in the same duration range. Two animation bugs fell out of it: the project dashboard's hover ignored `-disable-animations`, and the command palette's transition never ran because nothing animated the condition that mounts it — it now scales in from the top.
- Controls acknowledge the pointer. The two shared button styles now light up under the cursor — a ghost button was previously indistinguishable from a label — and every button gives slightly under the click and springs back. Icon buttons across the sidebar, session header, attention centre, editor control and file tree went with them.
- Prose and data are set in different faces. Mono stays the product's voice on everything that *is* data — ids, paths, branch names, log output, counters, project and session titles — while sentences a person reads (the whole first-run flow, the Extensions screen title and description, empty states) are set in the system face. A paragraph in a terminal face is what made a careful interface read as a developer utility.
- The Extensions search heading still said "Arama"; it says "Search".
- The Extensions window got the same pass. Its navigator, package cards, catalog cards and the rows inside the catalog detail sheet all answer the pointer now — a grid of entirely-clickable cards that reacted to nothing was the worst of it; a card picks up the accent edge and lifts. Disclosure chevrons turn instead of jumping, and the descriptions, summaries, remedies and empty states are set in the prose face while names, versions, paths and counts stay mono. Settings needed none of this: it is built on the platform's own list and controls, which already carry macOS's hover and press behaviour.

- The first-run welcome page shows the full application icon rather than the menu-bar glyph, which was drawn at 17×24 with an inset and read as thin and soft at display size.

- A performance and memory pass across the app. Rendering: session status updates now publish only real changes (hook and PTY events repeat the same status many times a second, and each publish re-rendered the whole window), long lists — packages, updates, task rows, session cards and history — build only their visible rows, run history is no longer re-read from disk at log-output frequency, the Keychain is no longer queried on every catalog render, status orbs draw at 15 fps and stop entirely under `-disable-animations`, and live window resizes no longer walk the whole view tree per frame. Memory: ended sessions release their handlers and keep at most the four most recent terminal buffers, the catalog detail cache is bounded (each entry can carry a skill's whole file set), only the newest 500 audit lines are decoded at launch, resolved permission records expire after seven days, Codex sessions no longer leak per-turn item state or the server log handle, the security scanner streams past files over 16 MB and hashes bytes without a second copy, Bumblebee output is capped at 4 MB like every other process runner, and the command palette lets its file index go when it closes.

### Fixed

- Cleared and read notifications stayed cleared. Marks were dropped for any row that left the list, and task rows leave it constantly — they come from a scan that runs on its own schedule and has produced nothing during the first refreshes of every launch — so every mark the user made was thrown away moments before the same rows came back. A row's absence is now only taken as "over" when the snapshot could have produced it: a session's status row while its session is present, a task row once the scan has produced something. Genuine recurrences still return unread, which is what occurrence signatures were always for.
- A skipped setup step counts as answered. Declining to add a project during first-run left "Finish setup" in the sidebar on every launch afterwards, forever; skipping is an answer, and a flow the user has been through has no remainder. Everything a skipped step would have configured is still in Settings, and About still restarts the whole flow.

### Added

- A project with no `TODO.md` is offered one, on its General page, with a sentence about what the file buys: a Tasks tab, agents assigned to checkboxes, review and merge. It writes a starter file on request — the same template first-run setup uses — and "Not for this project" retires it for that project permanently. Tasks were previously invisible to anyone who skipped the first-run step, since without a task source there is no Tasks tab to discover.

### Changed

- The Sessions panel's "Organise Automatically" is now a quiet heading action rather than a full bordered button that outweighed the panel it belonged to.

- The runtime daemon now reaps abandoned sessions: a session with no client attached for 24 hours that has shown no sign of life in as long is terminated (its agent CLI and MCP helper go with it). "Sign of life" is terminal output *or* CPU time — an agent quietly waking now and then to check a timer or a date burns CPU and is never touched, and a quiet-but-open session in the app stays the app's business. Without this, sessions left behind by quit apps and dev builds accumulated indefinitely.
- Finished the Turkish→English string migration the tests were still asserting against: 96 pre-existing unit-test failures traced to stale Turkish expectations and fixtures, plus genuine half-migrated output in code — fuzzy search had lost its Turkish case/diacritic folding ("gorev" no longer matched "görev"), the menu bar still said "kuyrukta/bloklu", quarantine audits said "(bulgu f1)", the stale-edit sheet mixed "# Your edit" with "# Dosyadaki hâli", and orchestrator plans said "Dalga N". The test scheme now pins `en-US` so the suite is deterministic on non-English systems. All 1418 tests pass.

### Changed

- Settings no longer uses the app's bespoke mono type and hand-drawn panels. It is the one surface where matching macOS beats matching Uncoil, because that is where a user arrives with expectations from every other app they own.
- The menu-bar monitor's on/off switch moved out of `UserDefaults` and into settings.json alongside the rest of its options; a deliberate "off" from an older build is carried over on upgrade.
- Codex sessions run the Codex CLI again, the way Claude sessions run theirs. The app-server protocol speaks JSON rather than running a TUI, which left Uncoil owning the prompt, the history and the editing — and a new session opened onto a bare cursor with none of it. The protocol client stays behind `-codex-app-server` rather than being deleted: structured approvals and turn state are built on it, and its tests still run.
